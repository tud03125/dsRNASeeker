# Null-Z execution reliability candidate

The existing randomized Eulerian dinucleotide shuffle, pair-specific seed, ViennaRNA command options, shuffled duplex and monomer MFE calculations, and mean/sample SD/Z definition are unchanged. The old serial routine remains as a regression reference. Execution uses a bounded worker pool. Each complete pair is checkpointed atomically under `.dsrna_nullz_cache` in the run directory (shared between conditions); optionally set `DSRNA_NULLZ_CACHE` to an absolute cache directory for controlled cross-radius reuse. Cache keys include ordered sequences, pair ID, observed ddG, requested N, seed, Python/library versions and source/executable/library fingerprints. No existing unverified aggregate TSV is accepted. Incomplete replicates stop the stage; zero variance legitimately yields missing Z. Keep the same output directory and cache to resume, with a single writer per output directory. Cross-run caches should be private to trusted users, and use a fresh output directory when changing upstream settings. No automatic use of historical unverified Null-Z values. Set `DSRNA_NULLZ_WORKERS` to the desired worker count, bounded by SLURM_CPUS_PER_TASK or pipeline threads; each worker runs serial folding commands. More workers can increase peak memory, particularly for long arms. The patch does not change the ADPS formula or IntaRNA. Tests compare legacy and updated output and verify cache behavior, not full FASTQ runtime. No performance claim until measured on representative datasets.
