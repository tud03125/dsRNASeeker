# Production reliability update (candidate, not historical benchmark replacement)

IntaRNA is optional ancillary output; ADPS does not use its E column. The historical environment allowed an incompatible legacy 1.2.5 executable. When `--do-intarna` is supplied, the updated implementation performs a finite-energy synthetic preflight before expensive processing, preserves the exact query/target ordering and CSV E column, distinguishes successful and header-only no-interaction predictions, and stops on execution/parse errors with diagnostics. Output TSV retains `pair_id` and `E`; status and provenance are separate sidecars. An old table without a matching provenance sidecar is recomputed. Use one writer per run directory. A failed run is not a valid new result. Use new output directories when changing module flags or configurations. Do not interpret the absence of an IntaRNA file as proof of a disabled run without checking parameters.

The revised environment specification is a candidate pin (`intarna=3.4.1`); validate a fresh environment before release. Existing benchmark environments and historical explicit locks are archival, not equivalent to this candidate installation. A separate compatible executable can be selected using `--intarna-exe /absolute/path/to/IntaRNA` on a clean new run. Do not mutate a running historical environment. `tests/test_intarna_checked.py` covers parsing, cache rejection, failure propagation and invalid input. For real-tool validation, use `tests/validate_structure_v2.py --fasta /path/to/duplex.clean.fa --out /new/test/directory --intarna /path/to/IntaRNA`. Run it in a dedicated allocation and set SLURM_CPUS_PER_TASK / DSRNA_STRUCT_WORKERS / DSRNA_STRUCT_CHUNK as appropriate.

Execution-only production model-v2 cofold, ddG and BPP parallelization is **opt-in**, after local real-tool regression: `export DSRNA_STRUCT_OPT=1 DSRNA_STRUCT_WORKERS=8 DSRNA_STRUCT_CHUNK=4` (use workers no greater than allocated CPUs; set OMP_NUM_THREADS, OPENBLAS_NUM_THREADS and MKL_NUM_THREADS to 1). It invokes the same v2 algorithms and preserves the six interface fields. Optional cross-run cache reuse: `DSRNA_STRUCT_CACHE_RUNS` is a colon-separated list of previously completed compatible run roots (each containing condition subdirectories); the wrapper checks ordered sequences, pair IDs, stage manifests and software/code fingerprints. No import of historical July structure results. Existing cache without a manifest is not trusted. For IntaRNA subprocess concurrency, set `DSRNA_INTARNA_WORKERS` up to the allocated CPUs; default 1. Null-Z retains its original implementation; per-chunk durable checkpointing, IntaRNA cross-radius caching and complete cache fingerprinting of shared libraries/custom energy parameters are not implemented in this candidate. A final table is atomic, not a checkpoint of partially completed calculations. Do not claim a measured speedup unless measured on comparable hardware and inputs. Use the serial mode by default until validated.

Historical J2 runs and labels are not changed. Their optional IntaRNA output contains no finite energies due to a CLI incompatibility; those energies were not used in ADPS. Historical resource measurements must retain their original configuration, including optional modules disabled. Do not overwrite old benchmark artifacts, environmental snapshots, or release tags. For a validated new release, publish a separately named new Linux explicit lock, record the commit and validation configuration, and synchronize archive/documentation references. The complete current source tree and whole FASTQ workflow are not validated merely by a few structural smoke pairs.
